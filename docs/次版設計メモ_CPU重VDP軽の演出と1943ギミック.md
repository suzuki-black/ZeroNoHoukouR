# 次版設計メモ ― CPU重・VDP軽の派手演出と「1943 感」ギミック

本メモは「零の咆哮 改（BattleshipProtoR）」の終わりに書いた、**次版（turboR の実力を見せる派手版）**の企画の叩き台。
**その次版が本リポジトリ「真 零の咆哮」**である。したがって本メモは**出発点の記録**であり、
いまの実装そのものではない。何がどうなったかは下の仕分け表を見ること。
根拠は前作で実測した性能特性（[性能と高速化.md](性能と高速化.md) / [苦労と教訓.md](苦労と教訓.md)）。

### 見送った
| 案 | 理由 |
|---|---|
| ★C の**面内回転**（回りながら沈む） | 16×16 の面内回転は中間角で形が読めない。見下ろしの宙返りは**回転ではなく縦の圧縮**に置き換えた |
| R800 のハード乗算（MULUW）を演出に使う | 検証はしたが、アフィン変形の内側ループに乗算は要らないと分かり本番では不使用 |
| エネルギー制ライフ（ゲージ＋自然減） | 設定の「耐久 1〜9」のまま |
| 対地／対艦ボム | B ボタンはメガクラッシュに割り当てた |
| ウェポンの時限式 | ミス・新規ゲームで戻す方式にした |
| ROM を 4〜8Mbit へ拡張 | 512KB のまま収めた（空きバンクは実質ゼロ） |

## 0. 現状の FPS 余裕率（何がどれだけ余っているか）

- **CPU 側**: §4-3（page1/ホットコードの RAM 実行）で計算が 1 VBLANK 内に収まり **60fps 相当**に到達
  （OVER1VB 25→1/60）。だが**ゲーム速度がフレームレート依存**のため、意図的に **30fps 固定**（ステージは
  2 VBLANK 待ち）にしている。
  → つまり現状は「60fps 分の計算を済ませて、**残り 1 VBLANK ぶんを毎フレーム捨てている**」。
  **CPU 予算はざっくり“もう 1 フレーム分まるごと空いている”**（＝実効の余裕率 ≈ 約2倍）。
- **さらに R800 の伸びしろ**: ホットコードを内蔵 RAM で回すと Z80 比で数倍速い。**RAM 常駐のまま重い演算を
  足しても、VDP に触らなければ turboR ではまだ相当詰める**。
- **VDP 側（＝ここが天井）**: VDP ポート I/O は R800 でも速くならない（1 アクセス ~7μs 級の強制ウェイト）。
  全画面 G4 は約 27KB/frame＝CPU→VRAM 直書きでは 30fps でも到底回らない。**戦闘中の実測 I/O は ~519 回/frame**で、
  ここを増やすと即カクつく。
- **結論（設計の芯）**: **余っているのは CPU、詰まっているのは VDP。** 次版の派手さは必ず
  **「重い計算・軽い出力」**＝R800 で大量に計算し、VRAM に流す量は最小、で作る。

## 1. 何が VDP を食い、何が食わないか（判定表）

| 手段 | VDP コスト | R800 で軽くなるか | 派手さの出し方 |
|---|---|---|---|
| CPU→VRAM 直書き（全画面 FB） | **激重**（帯域天井） | ❌ 不変 | 使わない。使うなら小領域/低頻度のみ |
| VDP コマンド（LMMV/LMMM/HMMM） | 中（発行 I/O＋VRAM 帯域。ただし**VDP が並列実行**） | 発行数は不変だが CPU と重ねられる | バルク転送は VDP に任せ、裏で R800 が次を計算（§4-1 の並列） |
| **パレット書換（R#16/17 間接）** | **極軽**（16 エントリ＝VRAM の数千分の1） | ― | 全画面の色を毎フレーム変える＝“光る/染まる”が激安 |
| **HW スクロール（R#23/R#26-27）** | **極軽**（数レジスタ） | ― | 背景全体を動かす/揺らす |
| スプライト属性（SAT 一括バースト） | 軽〜中（32枚上限） | ― | 少数の主役だけ HW スプライト |
| **RAM 内の純計算**（物理/幾何/LUT） | **ゼロ** | ✅ 大幅 | ここに R800 を全振り＝turboR の見せ場 |

**設計の合言葉**: 派手さの担い手を「**VRAM に書く量**」から「**R800 が計算する量**」へ移す。
出力は「パレット・スクロール・少数スプライト・低頻度/小領域の VDP コマンド」に押し込む。

## 2. CPU 重・VDP 軽・視覚効果大の演出カタログ（次版の一発芸）

各項: **何を R800 が計算するか / VDP コスト / なぜ Z80 不可 / 難度**。★=費用対効果が高い順。

### ★A. パレットで殴る全画面演出（コスパ最強・最優先）
- **計算**: R800 が毎フレーム 16 色パレットを再計算（グラデ流し・被弾赤染め・稲妻の全画面フラッシュ・
  擬似ライティング・水面の色サイクル・ボス出現の明滅）。512 色から動的に選ぶ演算は R800 向き。
- **VDP コスト**: 16 エントリ書換のみ＝**ほぼゼロ帯域**。
- **Z80 不可の度合い**: 単純なら Z80 でも可。**毎フレーム“計算したパレット”**（環境光/減衰/HDRっぽい調子）を
  凝るほど R800 差が出る。
- **難度**: 低。**まず最初に入れるべき“turboR は全画面を只で光らせられる”デモ**。

### ★B. 全画面ディストーション（衝撃波・熱陽炎・水面うねり）
- **計算**: R800 が**低解像度の変位マップ**を計算（撃破の衝撃波リング、熱の揺らぎ、爆風）。
- **VDP コスト**: 変位を**小さいバッファで計算 → 1〜数回の VDP コピー/拡大で提示**。全画面を毎回描かない。
- **Z80 不可**: 毎フレームの per-cell 変位計算は Z80 では間に合わない。
- **難度**: 中。破壊スペクタクルの核。前作「炎はバッファ B に焼く」思想の発展。

### ★C. アフィン変形ボス（回転＋拡縮）― 「これ MSX!?」の代表
- **計算**: V9958 に回転・ズームは無い。R800 が**毎ピクセルの元アドレス**を回転行列 LUT＋`MULUW`（R800 の
  ハード乗算）で算出。ボスが回りながら沈む／巨大化して迫る。既存の艦アセットがそのまま“回る素材”。
- **VDP コスト**: 差分タイルだけ転送。ボス演出は 20〜30fps で十分＝更新頻度を落として帯域を稼ぐ。
- **Z80 不可**: リアルタイム・アフィンは Z80 では非現実的。**MULUW は R800 専用命令＝直球の見せつけ**。
- **難度**: 中〜高。

### D. 本物の弾幕（ハード制約を計算で踏み越える）
- **計算**: HW スプライトは 1 走査線 8 枚・総 32 枚＝**本当の弾幕は不可能**。R800 が**数百発の曲線軌道**を計算し、
  CPU コンポジットの点群として小型 FB に置く。
- **VDP コスト**: ダーティタイルだけ転送。弾の色数を絞る（1〜2 色）ほど軽い。
- **Z80 不可**: Z80 は数十発、R800 は数百発＝数の桁が違う。
- **難度**: 中〜高。1943 の“弾を避ける密度”を底上げする（§4 と直結）。

### E. 数千パーティクル物理（轟沈の火の粉・破片）
- **計算**: 撃沈で破片・火の粉を**数千個、重力＋速度**で更新。粒子更新は R800 の独壇場。
- **VDP コスト**: 点描で FB へ。粒子は 1px＝書込は小さい。
- **難度**: 中。撃破の“物量”で turboR 差を体感させる。

### F. 3D 波の海／ボクセル地形
- **計算**: 海面を**ハイトマップのレイキャスト**で起こし、うねる立体の海を飛ぶ／巨大メカボスをボクセルで。
- **VDP コスト**: 縦カラム単位で描き、HW スクロールと組み合わせて帯域を分散。
- **難度**: 高。純演算の塊＝turboR の底力そのもの。既存の海テンプレを高さ場に再利用可。

### G. タイル入替アニメ（大面積を安く動かす）
- **計算**: 巨大背景（はためく旗・morph する地形）を**「どのタイルを置くか」だけ R800 が決定**。
- **VDP コスト**: ピクセルでなく**名前/配置を差し替える**＝安い。G4 なら VRAM のタイルバンクから LMMM で
  VDP に貼らせる（VDP が並列で肩代わり）。
- **難度**: 中。帯域を食わず“大きく動いて見える”王道。

**推奨着手順（費用対効果）: A → B → D → C → E →（余裕で）F/G。**
A/B/D で「安く派手」を確立してから、C/F の“重演算ショーピース”をボスに一点投入する。

## 3. 演出を成立させる帯域予算の鉄則（前作の教訓）

派手さの敵は最後まで **VRAM 帯域**。成功する見せ場は必ず次のどれかを満たす：
1. **出力が小さい**（低解像度の場を計算→VDP 拡大で見せる）。
2. **更新頻度を落とす**（ボス/カットは 20〜30fps でよい）。
3. **領域を限る**（全画面でなく帯・窓）。
4. **VDP コマンドに並列で肩代わりさせ、裏で R800 が次を計算**（§4-1）。ただし**VRAM を触る CPU 直書きと
   VDP コマンドは重ねない**（§3-9 の教訓＝両方遅くなる）。

**“何を計算するか”より“何を VRAM に書かないか”の設計がこの企画の 9 割。**

## 4. 「1943 感」を出すための自機・敵機ギミック／パワーアップ

現行は「避けて壊す」純アーケードで、1943 的な**成長・爽快・物量**が薄い。1943 の実要素を踏まえ、
turboR の CPU 余裕と噛み合うものを優先して列挙する（◎＝§2 の CPU 見せ場と両取り）。

### 4-1. 自機まわり（プレイ感の核）
- **◎ 宙返り回避（loop-the-loop）**: 1943 の看板。ボタンで自機が宙返り＝**一瞬無敵＋弾消し**。演出は
  自機スプライトの**回転（§2-C のアフィン）**で見せられる＝**1943 ギミックと turboR ショーの両取り**。
- **エネルギー制ライフ（体力ゲージ＋自然減）**: 即死でなく、被弾と時間経過でゲージが減り 0 で撃墜。1943 の
  “粘り”の肝。アイテムで回復。現行の「耐久 1-9」をゲージ表示＋時間減衰へ拡張。
- **ウェポン・パワーアップ（時限式）**: 3-way / ショットガン（前方拡散）/ オート（連射）/ ワイド。**弾数が増える
  ほど §2-D の CPU 弾計算が映える**＝爽快さと turboR 誇示が一致。時限で素に戻る 1943 流。
- **メガクラッシュ／稲妻（画面消去の必殺）**: 全画面フラッシュ（§2-A パレット）＋衝撃波（§2-B）＋敵弾全消し。
  **安い出力で最大の爽快**。回数制限アイテム。
- **副武装（対地/対艦ボム）**: 上方弾とは別に、艦の甲板/対空砲へ落とすボム。1943 の“対地攻撃”の再現。

### 4-2. パワーアップの供給（1943 の「POW」流）
- **特殊敵撃破でアイテムドロップ**: 編隊中の**光る敵機**や特定の艦載機を全滅させると POW/武器/回復が出現。
- **アイテムの見せ方**: 出現・取得を §2-A のパレット明滅で目立たせる（帯域ゼロで派手）。

### 4-3. 敵・ウェーブの多様化（“空戦の物量”で 1943 感）
- **編隊ウェーブ**: 直線/V字/旋回で入ってくる**敵機の編隊**（現行の単発湧きから増強）。各機の軌道は R800 が
  計算＝CPU 余裕の使い道。
- **雑魚と対地目標の混在**: 海上の潜水艦/小艇/対空陣地を**ボムで潰す**対地レイヤ（1943 は空と地/海の二層）。
- **弾幕の底上げ**: ボスの発砲を §2-D の CPU 弾で密度アップ（避ける快感）。**ただし避けられる設計**（宙返り・
  ゼロ距離抑え込みで対処可能に）を守る。
- **中型艦の道中ボス**: 大型艦の前に破壊可能な中型目標を挟み、テンポと達成感を刻む。

### 4-4. スコア/爽快の演出（1943 の“気持ちよさ”）
- **撃破の物量演出**: §2-E 数千パーティクル＋§2-B 衝撃波で“沈む重さ”。
- **ボーナス/コンボ**: 連続撃破・ノーミス・パーツ全壊ボーナス等。現行のスコアポップアップを拡張。
- **リザルトの派手化**: 撃沈カットに §2-C アフィン（艦が傾いて沈む）を一点投入。

### 4-5. 優先度（1943 感への効き × 実装コスト）
1. **宙返り回避**（看板ギミック＋turboR 回転ショー。効き大） 
2. **ウェポン・パワーアップ＋POW ドロップ**（爽快の核。CPU 弾と両取り）
3. **エネルギー制ライフ**（粘りのプレイ感）
4. **メガクラッシュ**（安く最大の爽快）
5. **編隊ウェーブ＋対地ボム**（空戦の物量・二層化）

## 5. まとめ（次版の一枚岩の方針）

- **余っているのは CPU、天井は VDP。** 派手さは全て「重い計算・軽い出力」で作る（§2/§3）。
- **turboR 誇示と 1943 感が最も噛み合うのは「宙返り回避（=回転ショー）」「ウェポン強化（=CPU 弾の物量）」
  「メガクラッシュ（=パレット＋衝撃波）」**の 3 つ。ここから着手すれば、**面白さは別としても“turboR すごい”と
  “1943 っぽい”を同時に取りに行ける**。
- 実装は **A（パレット）→ B（歪み）→ D（弾幕）** で安く派手を確立し、**宙返り/パワーアップ/メガクラッシュ**を
  ゲーム側に足していく。ボスに **C（アフィン）/F（3D 海）** を一点投入して“ショーピース”を作る。
- ROM は 4-8M へ拡張し、**LUT（sin/cos・逆数・回転元アドレス・パーティクル/回転パターン・パレットグラデ）と
  面別エフェクト payload** に使う（生の動画に使わない＝帯域が死ぬ）。

> （ただし MULUW は不使用。詳細は冒頭の仕分け表と [アルゴリズム解説](アルゴリズム解説.md) §17）。
