# ハイスコア機能 設計メモ

> 状態: **設計のみ（未実装）**。2026-09-27 に調査してまとめた。
> ★執筆時点では実機（turboR 実物）が無く、保存の可否は WebMSX の実装を読んだ結果と仕様書に
> 基づいている。本書で「実機」と書いてある箇所は **WebMSX の turboR 設定での確認**のこと。
> **2026-09-30 に実機が使えるようになった**ので、実装するときは**実機の SRAM で確かめ直すこと**
> （WebMSX の SRAM の持ち方と実機は別物の可能性がある）。

## 1. いまどうなっているか

- `g_score`（u16、5桁）と `g_hiscore`（u16）があり、**電源を切ると消える**（セッション内のみ）。
- 表示は 2 か所。ゲームオーバー画面（`ship_render.c`）と撃破結果画面（`gen_planes.c`）に `HI` として出る。
- 名前入力もランキングも無い。

## 2. 作るもの（仕様案）

### 2-1. ランキング表

| 項目 | 幅 | 備考 |
|---|---|---|
| スコア | 2B | u16（5桁）。いまのスコア体系だと 6 面通しでも 65535 には届かない見込み |
| 到達面 | 1B | 0..5（1面..最終面）。クリアしたら 6 |
| 名前 | 3B | `A`〜`Z` と空白。ASCII で持つ |
| 予備 | 2B | 日付を入れたくなったとき用（時計ICから読める）。当面 0 |

5 件 × 8B = 40B。これに署名と版とチェックサムを足して **48B**。

### 2-2. 流れ

```
ゲームオーバー（残機0・コンティニューしない）
  └→ 5位以内か？  ── いいえ ─→ ランキング表示 ─→ タイトル
        └ はい ─→ 名前入力（3文字）─→ ランキング表示（自分の行を点滅）─→ タイトル
最終面クリア → エンディング → 同上
```

- 名前入力: 上下で文字、左右で桁、トリガで決定。`END` を選ぶか 30 秒放置で確定。
  文字は自前 8x8 フォント（`vdp_glyph`）をそのまま使う＝新しい絵は要らない。
- ランキング表示: SCREEN5 のテキスト描画（結果画面と同じ `vdp_text`）。
- タイトルは YJK の自然画なので**触らない**。ランキングはゲームオーバー後の独立した画面に出す。
  （タイトルで放置したらランキングを見せる「アトラクト」は、YJK 画の読み直しに 54KB かかるので後回し。）

## 3. 保存先（調査結果）

### 3-1. 時計IC（RP-5C01）の CMOS RAM → **使わない**

MSX2 以降の時計 IC には電池で保つ CMOS RAM があるが、

- **block 2** … BIOS が起動時の画面モード・色・キークリック・ボーレート等に使っている
- **block 3** … 起動画面の**タイトル文字列**または**パスワード**（BASIC のプロンプト）

つまり空きが無く、勝手に使うと**ユーザーの起動設定を壊す**。ここは諦める。

### 3-2. カートリッジ SRAM（ASCII8 + SRAM）→ **本命**

ASCII8 マッパにバッテリ付き SRAM を足した形式（`ASCII8SRAM2/8` = 通称 `KoeiSRAM`）。
WebMSX の実装（`CartridgeASCII8KSRAM`）を読んで確かめた仕様:

- バンクレジスタは ASCII8 と同じ **0x6000 / 0x6800 / 0x7000 / 0x7800**。
- **SRAM 選択ビット** `j = max(32, 2^ceil(log2(ROM の 8KB ページ数)))`。
  本作は 512KB = 64 ページなので **`j = 0x40`**。
- ページ2の下半分（0x8000-0x9FFF）はレジスタ 0x7000、上半分（0xA000-0xBFFF）は 0x7800。
  そこへ `0x40` を書くと、その 8KB 窓が **SRAM になり、読み書きできる**。
- 0x4000-0x5FFF に SRAM が出るのは Koei 形式のときだけ。本作では使わない。
- WebMSX で試すには URL に **`ROM_FORMAT=ASCII8SRAM8`**（別名 `CART_FORMAT`）を付ける。
  付けないと素の ASCII8 と判定され、SRAM は存在しない。

★ **実機のフラッシュカートで SRAM が見えるかは未検証**（転送ハードが未着）。
見えなければ 3-3 のとおりセッション内のみに落ちるだけで、ゲームは普通に動く。

### 3-3. 実装はプローブ方式にする

決め打ちにせず、**起動時に 1 回だけ調べる**:

1. page2 が cart の文脈で、0x7000 に候補ビット（`0x40` → `0x80` → `0x20`）を書く
2. 0x8000 に署名を書いて読み戻す。**元の ROM の中身と違う値が読めたら SRAM がある**
3. 見つかったビットを `g_sram_bit` に覚える。見つからなければ 0（＝保存しない）
4. 最後に必ず元のバンク番号へ戻す

★ **page2 は演出中に RAM へ差し替える**（`ramx_use_ram`）ので、SRAM を触るのは
page2 が cart のときだけ。触った後はバンクを元に戻す（戻し忘れると画面が壊れる）。

### 3-4. 保存の中身（SRAM 先頭 48B）

```
+0  'Z' '5'      署名（この 2 バイトが無ければ初期化する）
+2  版(1B)       表の形を変えたら上げる。違う版は捨てて初期化
+3  件数(1B)     5
+4  5件 × 8B     スコア(2) 到達面(1) 名前(3) 予備(2)
+44 予備(3B)
+47 チェックサム(1B)  0..46 の総和の 2 の補数（壊れていたら初期化）
```

書くのは**ランキングが変わった瞬間だけ**（名前確定の直後）。ゲーム中は触らない。

### 3-5. ディスクへの保存は対象外

カートリッジから起動するので MSX-DOS は載っていない。セクタ直書きは他人のディスクを
壊しうるのでやらない。

## 4. 置き場と見積り

いまの枠（2026-09-27 時点の実測）:

| 枠 | 使用 / 上限 | 残り |
|---|---|---|
| 常駐コード bank0-2 | 24,244B / 24,576B | **332B**（ほぼ無い） |
| 常駐 RAM `_DATA` | `s__HEAP=0xDE36` / 天井 0xE000 | 458B |
| bank5（タイトル） | 87B / 8,192B | 8,105B |
| bank6（設定） | 1,120B / 8,192B | 7,072B |
| bank7（エンディング） | 1,561B / 8,192B | 6,631B |
| 空きバンク | — | 1 本（8KB） |

- **コードは冷たいバンクへ**。常駐に 332B しか無いので、名前入力もランキング描画も
  バンクシーン側に置く。エンディングと同じ **bank7** に相乗りさせるのが素直
  （ゲームオーバー → ランキング → タイトル の流れで、エンディングと同時には動かない）。
- **表は常駐 RAM**（48B）。`s__HEAP` はリンクで動くので、天井から下ろした固定番地
  （例: 0xDF00）に `__at` で置き、`s__HEAP <= 0xDF00` を Makefile で機械検証する。
- 常駐に増えるのは「新しいシーン ID とその分岐」だけ（数十バイト）。

見積り（バンク内）: 名前入力 ≒ 700B / ランキング描画 ≒ 400B / SRAM 読み書き ≒ 200B
＝ **約 1.3KB**。bank7 の空きで十分足りる。

## 5. 段階

| 段 | 内容 | 判断 |
|---|---|---|
| P1 | ランキング表（RAM）＋名前入力＋ランキング画面。保存はしない | これだけでも遊びとして成立する |
| P2 | SRAM プローブ＋保存・読み込み | WebMSX は `ROM_FORMAT=ASCII8SRAM8` で確認。実機は要検証 |
| P3 | タイトルで放置したらランキングを見せる（アトラクト） | YJK 画の読み直し 54KB の扱いを決めてから |

- 名前入力を入れるとゲームオーバーからタイトルまでが長くなる。テンポは実際に触って調整する。
