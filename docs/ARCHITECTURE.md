# アーキテクチャ — 真 零の咆哮（turboR 専用エンジン）

> 系譜: 零の咆哮（BattleshipProto, C＋Z80）→ 零の咆哮 改（BattleshipProtoR, turboR 専用エンジン）→ **本作**。
> 改で作った「常駐を薄く保ち、熱いコードは RAM で実行する」土台の上に、**演出は RAM オーバレイと走査線割込み**で
> 積み増している。この文書は「何がどこに置いてあるか」と「置き場所の規律」を書く。
> 数値は 2026-09-23 のビルド実測。

## 1. メモリ地図（Z80 64KB 空間 と ASCII8 MegaROM）

```
Z80アドレス空間                          ASCII8 MegaROM(512KB = 64 bank × 8KB)
┌───────────────────────────┐          ┌──────────────────────────────────┐
│ 0x0000-0x3FFF page0 = BIOS │          │ bank0  ROM 0x00000  ┐             │
│ 0x4000-0x5FFF ← bank0      │◀────────▶│ bank1  ROM 0x02000  ├ 常駐コード   │
│ 0x6000-0x7FFF ← bank1      │  ASCII8  │ bank2  ROM 0x04000  ┘ (<=24KB)    │
│ 0x8000-0x9FFF ← bank2      │  4窓      │ bank3..63           = 冷コード     │
│ 0xA000-0xBFFF ← 窓/オーバレイ│◀────────▶│                       ＋データ     │
│ 0xC000-0xFFFF page3 = RAM  │          │                                  │
└───────────────────────────┘          └──────────────────────────────────┘
   窓の切替は 0x6000/0x6800/0x7000/0x7800 への書込。0x7800 = 0xA000窓(スワップ)。
```

- **bank0-2 = 常駐コード(0x4010-0x9FFF, 24KB 上限)**: 起動時から居続ける“熱い”コード。
  `rompack.mjs` が **24KB 超過をビルドエラー**にし、毎ビルドで残量を表示する（硬い天井を機械強制）。
  現況 **24,127B / 24,576B（残り 449B）**。デバッグ版(`DEBUG_FPS=1`)は 24,529B（残り 47B）。
- **0xA000-0xBFFF は二重用途**。page2 が cart の間は **ASCII8 のスワップ窓**（`bcall`/`data_read` が使う）、
  page2 を RAM 化している区間は **RAM オーバレイ領域**（§3.12）。bank3 は「窓の既定ページ」という規律は
  残っているが、**ROM の bank3 自体は 5面の中ボス用オーバレイに使っている**（窓を差し替えたまま帰らなければよい）。
- **ROM は 512KB**。128KB→256KB→512KB と 2 度拡張した。最終面のボスのコマ（80KB 超）と中ボス5種の絵で、
  **空きバンクは実質ゼロ**（bank29 は DEBUG_PROF、bank31 は HSTEST の予約枠）。

### RAM（page3 = 0xC000-0xFFFF）の固定番地

常駐 `_DATA` は 0xC000 から。**天井は 0xE000**（`s__HEAP <= 0xE000` を Makefile がリンク後に機械検証）。
0xE000 から上は「冷たい大物」と「同時に使わないもの同士」を手で重ねて置いている。

| 番地 | 中身 |
|---|---|
| 0xC000〜 | 常駐 `_DATA`。この中に `hot_ram[HOT_CAP=5696]` を予約（現況の末尾 `s__HEAP=0xDE36`） |
| 0xE000–0xE0FF | **バンクシーン/バンクコードの static**（同時にアクティブなのは1つ。256B を超えると 0xE100 を踏む） |
| 0xE100–0xE6FF | 開始カードの作業 `g_card_ram[1536]` ＝ 現在の曲 `bgm_ram[1536]`（時期が重ならないので共用） |
| 0xE500〜 | He 111 の機体色 448B（4面の中ボス中のみ） |
| 0xE700〜 | 艦体OPS の展開 `ship_ram` ＝ **中ボスの向きデータ `MB_BUF`(1KB)** ＝ 警報の作業行（面の準備と中ボスは同時でない） |
| 0xE900〜 | 火球の作業 `fb_ram[512]` |
| 0xEB00〜 | DEBUG_PROF の計測 |
| 0xEB80〜 | 中ボスの影パターン `MB_SBUF`(128B) |
| 0xEC00–0xEDFF | **CPU 弾幕 `g_cbul[64]`(512B)**。中ボス戦の間は弾幕が出ないので、**中ボスの背景弾の表(0xEC00)と海のひな形(0xED00)** が借りる。最終面も同じ帯を別用途で借りる |
| 0xEE00–0xEEFF | **RAM オーバレイの static（256B 厳守）**。超えると 0xEF00 の分割表を壊す（実際に踏んだ） |
| 0xEF00〜 | **走査線分割表 `g_ras[12]`**（8B/件） |

## 2. 常駐 vs バンク vs オーバレイ — 何をどこに置くか（規律）

### 常駐（bank0-2, 24KB）に置くもの＝毎フレーム/割込みで必ず要る核だけ
crt0＋`_bcall`（`crt0rom.s`）／VDP（`vdp.c`）／バンク切替（`bank.c`）／入力（`input.c`）／シーンFSM（`scene.c`）／
起動初期化（`sys.c`）／H.TIMI 音ドライバ（`sound.c`）／**走査線割込み（`raster.c`）**／エンティティ（`entity.c`）／
自機（`player.c`）／発砲（`fire.c`）／スクロール（`scroll.c`）／HUD（`hud.c`）／CPU弾幕の器（`curtain.c`）／
**オーバレイ読み込み（`overlay.c`）**／RAM実行（`ramexec.c` / `hotcode.c`）／面の進行（`scene_stage.c`）。

`ops.c`（旧 run_ops）は**リンクから外してある**。艦の描画は bank16 の `ship_render` に独自実装があり、
常駐に置いた解釈器は誰も呼んでいなかった（197B の無駄だった）。

### バンク（bank4+）へ回すもの＝冷たい/一度きり/データ
各シーンの重い init/draw（title・config・ending）、艦レンダラ、面の準備、戦闘機の生成、絵・曲・文字列。
→ コードが冷たいなら **bcall**、データなら **`data_read` で先読み**。

### RAM オーバレイ（0xA000-0xBFFF）へ置くもの＝毎フレーム回る“演出”
中ボス・最終面のボス・撃沈・メガクラッシュ・宙返り・パレット・CPU弾幕・増槽。詳細は §3.12。

### バンクコード3原則（破ると暴走）
1. **呼び先は 0xA000 単一エントリで自己完結** — 常駐関数は注入番地で呼べるが、データ窓は読まない。
2. **呼び元は必ず常駐(<0xA000)** — 切替中に 0xA000 のコードを踏まない。
3. **切替中は di、済んだら既定へ復元** — `_bcall` が担保（`crt0rom.s`）。

### 割込み文脈のコードは 0x6000 未満に置く（オーバレイの副作用）
`overlay_load` は 8KB を複製する。**di で囲むと 223ms 割込みが止まり、BGM ごと固まる**ので、複製中は割込みを通す。
その代償として、**割込みから呼ばれるコードは複製で差し替わる窓(0x6000-0x7FFF)に居てはいけない**。
`ras_apply` / `ras_rearm` / `ras_isr` / `sfx_update` / `bgm_update` / `snd_isr` / `sound_init` と、
窓を自分で差し替える `ramexec_page2_to_ram` / `overlay_load` の**番地を Makefile がリンク後に検証**している。

## 3. 仕組み

### 3.1 シーンFSM（`scene.h` / `scene.c`）
`Scene { init(); update()->次ID; bank }` の表 `registry[]` に集約し、`scene_run()` が
「入場時 init 1回 → 毎フレーム update → 戻り値で遷移」を回す。シーンは **SC_TITLE / SC_CONFIG / SC_STAGE / SC_ENDING の4つ**。

- 起動＝`SC_TITLE`（bank5）。トリガで `SC_STAGE`。タイトルで**コナミコマンド(↑↑↓↓←→←→BA)**を入れると `SC_CONFIG`（bank6）。
- **6面すべてが `SC_STAGE` の中**。面をクリアすると `curstage++` して `stage_intro()` を呼ぶだけで、シーンは変わらない。
  最終面（`STAGE_FINAL=5`、`STAGE_TOTAL=6`）をクリアしたときだけ `SC_ENDING`（bank7）。
- ミスは面の最初から。残機が尽きたら、継続ONでコンティニュー（無限）／OFFでタイトル。
- 冷たいシーンのバンク化: `registry` の `bank != 0` なら `call_scene()` が `g_scene_phase`(0=init/1=update) を
  セットして `bcall_to(bank)`。バンク側 `banked_entry` が phase を見て分岐し、次IDを `g_scene_ret` に書く。
- 設定には**画面ビューア**（`g_view`: 通常/開始カードのみ/結果画面のみ/エンディング）というデバッグ経路がある。

### 3.2 面の進行（`scene_stage.c`）
1〜5面は **海1 → フェードアウト → 中ボス → 海2 → フェードアウト → 警報「敵艦発見」→ 艦との戦い → 撃沈 → 結果**。
6面は **警報「敵大将発見」→ 電文 → 投棄 → ボス登場 → 交戦 → 撃墜 → 結果 → エンディング**。
数値（長さ・敵の間隔・耐久・得点）は [仕様書](仕様書.md) にまとめてある。

### 3.3 データ駆動の発砲（`fire.c`）
`FireDesc{interval, suppress, [op,a,kind,spd].., 0}`。op は FIXED / RING / **AIMED**（狙い＋一様乱数の円錐）/
**AIMFAN**（自機中心の n-way ＋扇全体の微回転）。方向は 32 分割（11.25°）。
**ゼロ距離抑え込み**（`suppress`=半径px）は、自機がその半径内なら発射を飛ばす＝肉薄すれば安全に撃ち込める、
という 1面の教育メカ。実効半径は難易度で ±（EASY 広い / HARD 狭い）。

### 3.4 連続縦スクロール地形（`scroll.c`）★設計の要
- 表示＝**page1 を 256px のリングバッファ**にして `R#23 = cam & 0xFF` で縦スクロール。
- 艦は**艦バッファ B に一度だけ事前描画**し、露出した16px の世界行だけ `draw_row`（LMMM 1本）でリングへ流す。
- 海は 16 行のテンプレートを敷き、**SEA13**（艦を避けた列だけを位相をずらして塗り直す）で擬似多重スクロール。
- リングに「今どの行を描いてあるか」は `drawn_top/drawn_bot` が持つ。**撃沈演出のように後から書き込む側は
  この範囲を見る**（cam から推測すると 256 行上の行を壊す。実際に踏んで「艦の途中に帯が抜ける」不具合になった）。

### 3.5 自機・当たり判定（`player.c` / `entity.c`）
- 当たり判定は `ent_resolve_collisions`（16x16 AABB、弾は ±6・体当たりは ±9）。被弾処理は `ent_player_hit` に集約
  （CPU弾幕・中ボスの弾・背景の弾もここを通る＝無敵時間・耐久・ミス判定・手応えが1か所）。
- **宙返り中は当たり判定そのものを行わない**（弾は自機の下を抜ける。消さない）。
- 得点: 敵機/停泊機 10 ／ 艦載機 20 ／ 小型対空砲 20 ／ 大型対空砲 30 ／ 主砲・最終面の弱点 60 ／
  中ボス 300〜900 ／ 増槽（最高段階で取得）1000。

### 3.6 スプライトの枠配分（`entity.c` の `ent_draw_all`）★可変
1セット32枚・1走査線8枚。**枠の配分は毎フレーム変わる**。

- HUD が先頭 `HUD_SLOTS=9`（スコア5桁・残機アイコン・残機数・ボム棒・残数）。`DEBUG_FPS` では 13。
- `g_spr_base` から自機→エンティティ→合体弾→影→点数ポップアップ→パワーアップのアイコン、の順に詰める。
- **宙返り中は `g_spr_base` が +4**（2×2 合成を HUD の直後に置く）。
- **5面の中ボス戦は `g_spr_base` が 0**（HUD を背景に描くので枠を全部ゲームへ回す）。
- 中ボスは普段**末尾**（混んだら中ボスが先に欠ける）。自機より高い所にいる間だけ**先頭**（`g_mb_front`）。
- `g_spr_limit` は「弾幕が出ている間は 32-12」「中ボス中は 32-中ボスの枚数」「アイコンのぶん -1」で下がる。
- 混雑ラインの落ち方を散らすため、**開始位置を毎フレーム回転**し、さらに**交互フレームで正順/逆順を反転**する。
- **枠 32 以上には絶対に書かない**（書くと SAT の控えを溢れて隣の変数を壊す。実際にパターン表が壊れた）。

### 3.7 サウンド（`sound.c`）
H.TIMI(60Hz) の ISR が `sfx_update` → `bgm_update`。PSG は melody=tone A（効果音に譲らない）、
bass=tone B（自機弾・被弾・宙返りの効果音が一時占有）、noise C（命中・破壊・雷鳴・地鳴り）。
曲は 11 本（タイトル0／面別1,3,4,5,6／ED2／海イントロ7／最終面8／中ボス9／警報10）。
曲データは bank8 にあり、`bgm_play` が現曲だけ RAM(`bgm_ram`)へコピーする＝**ISR はバンク窓を触らない**。

### 3.8 破壊・炎上（`scene_stage.c` / `hot.c`）
火点＝**主砲4基＋対空砲23基**。主砲はスプライト実体（8方向の可動砲身）、対空砲は実体を持たず配列で管理＝
スプライト枠を使わずに23基を破壊対応。撃破した火点は**艦バッファBへ火球を焼き込む**ので、スクロールしても
炎ごと流れ、枠も食わない。火点の表は 48 枠（27＋撃沈時の散布火球18）。

### 3.9 ホットコードの RAM 実行（`hotcode.c` / `banked/hot.c`）★性能の要
R800 は**カートリッジ ROM のコードフェッチが内蔵 RAM 実行の約3.8倍遅い**。毎フレームのホットパスを
bank17 に置き、起動時に `hot_load()` が `hot_ram[HOT_CAP=5696]` へ転写して、そこから実行する。
現在 RAM 実行しているのは `aa_update` / `aa_collide` / `ent_update_all`（behavior 群）と、
**中ボスの背景弾エンジン**（`hot_hb.c` の `hb_init`/`hb_fan`/`hb_update`/`hb_clear`）。
当たり判定も RAM 化を試したが速度が変わらなかったので常駐へ戻した。
**HOT_CAP は hot.bin の実サイズ以上**でなければならない（不足すると転写が末尾を落として常駐を壊す）。Makefile が検証する。

### 3.10 page1 / page2 の動的 RAM 実行（`ramexec.c`）
ゲームループのホット区間だけ、常駐コードのある page1（0x4000-0x7FFF）と page2（0x8000-0x9FFF）を
マッパー RAM へ切り替える。出入口は `ramx_use_ram()` / `ramx_use_cart()` の1対。
**RAM 中は 0xA000 のスワップ窓が消える**ので、`data_read` / `bcall` は区間の外でだけ呼ぶ。
複製元を読むため 0x6000-0x7FFF 窓を一時的に差し替えるので、**複製関数自身は 0x4000-0x5FFF に居ること**（Makefile が検証）。
失敗したら `g_ramx_ok=0` / `g_ramx2_ok=0` で ROM のまま動く（安全側）。A/B 計測用に `make NO_RAMX2=1`。

### 3.11 固定タイムステップ（30fps）
`scene.c` が `SC_STAGE` で `vdp_wait_frame()` を 2 回待って **30fps 固定**にしている。ゲーム速度が全部
フレーム数指定なので、速くなると全部が倍速になるため。**例外はメガクラッシュ中だけ 60fps**
（ゲームが止まっている＝速度定数に影響せず、津波の動きが滑らかになる）。

### 3.12 RAM オーバレイ（`overlay.c` / `overlay.h` / `ovl*.c`）★本作の中核
page2 を RAM 化している間、**0xA000-0xBFFF（seg5 の上位8KB）が丸ごと空く**。そこへ演出コードを載せる。
追加の RAM 消費ゼロ、R800 全速、8KB。入口は先頭のジャンプテーブル（`OVL_ADDR + 3*slot`, slot 0–23）。

| オーバレイ | bank | 中身 |
|---|---|---|
| `ovl.bin` | 18 | 通常面（パレット・メガクラッシュ・衝撃波・宙返り・増槽・CPU弾幕） |
| `ovl6.bin` | 27 | 最終面（XB-19、壁、背景の弾） |
| `ovl7.bin` | 28 | 撃沈シーン |
| `ovl8/9/10/11/12.bin` | 24/25/26/63/3 | 中ボス（1面 Fw200 / 2面 PBY / 4面 He111 / 3面 駆逐艦 / 5面 P-61） |

守らないと暴走する制約:
1. **ホット区間の中でしか呼べない**（page2 が RAM のときだけ 0xA000 がオーバレイ）。
2. オーバレイから `data_read` / `bcall` を呼ばない（窓が自分を追い出す）。
3. 読み込み（`overlay_load`）は page2 が cart の文脈で行う。
4. `g_ovl_ok` を見る（載らない機械では演出を飛ばして素の挙動にする）。
5. **共通部分は同じ .rel を同じ順でリンクする**（static の番地を 0xEE00〜 で揃える＝途中で差し替えても状態が続く）。

### 3.13 走査線割込み（`raster.c` / `raster.h`）
H.KEYI(0xFD9A) にフックし、R#19（走査線一致）と S#1 の FH で分割する。表 `g_ras[RAS_MAX=12]` は 0xEF00 固定。
用途は3つ:

- **スプライト表の切替**（R#5: A=0xEF / B=0xE7）＝ 32枚制限を上下の帯で使い回す。
  分割行をまたぐスプライトは**両方の表の同じ枠に同じ内容**を置く（片方だけだとちらつく）。
- **衝撃波**（R#23 を行ごとに変えて縦にうねらせる）。
- **帯ごとの横スクロール**（R#26/R#27）＝ 3面の駆逐艦を、描き直しゼロで左右に動かす。

★**turboR（WebMSX）で効く分割の間隔は 29 行まで**（帯6本。実機は未確認＝§5）。openMSX は 14 行でも全部効くので、
**エミュで詰めた間隔は実機で落ちる**。1本の分割で書けるレジスタは 2 本なので、3本必要なときは行をずらす。

### 3.14 中ボスの絵の運び方（`midboss.h`）
中ボスの絵は ROM（bank20〜62）にあり、オーバレイからは読めない。向きが変わったら
**オーバレイが `g_mb_req` に番号を置く → 常駐がフレームの終わり（ホット区間の外）で `MB_BUF` へ 1KB 読む →
次のフレームでオーバレイがパターン・色・位置を書く**、という受け渡しにしている。
1KB を一度に読むと割込みが止まってスプライトが数コマ消えるので、**128B ずつに分けて割込みを通す**。

### 3.15 背景に描く弾（`hot_hb.c` / `ovl_bgbul.c`）
中ボス戦はスプライトが HUD 9・中ボス 16〜18・アイコン 1 で埋まり、**自機と弾に 4 枠しか残らない**。
そこで中ボスの弾はスプライトをやめて表示リングへ直接描く。

- **5面 P-61**: `ovl_bgbul.c`（48発・差分描き。重なって変わらない行は触らない。実測 1発 0.13ms）。
- **1面・4面**: `hot_hb.c`（24発・小型版。C で書くと 1KB を超えて HOT_CAP に入らないので本体は asm）。

どちらも**位置は画面座標で持ち、描く行だけリング(y+cam)へ**置く（スクロールに引きずられない＝敵弾の規約）。
消すときは海のひな形で戻す。表とひな形は CPU 弾幕の固定帯を借りるので、**ボムで帯を潰されたら読み直す**。

## 4. ビルド系（`Makefile` / `config.mk` / `tools/*`）

- 常駐は**個別 .c → 個別 .rel**。`RESIDENT_RELS` に列挙してリンクする（巨大単一 TU を作らない）。
  **並び順に意味がある**（先頭に置いた `ramexec.rel` が 0x4000 台に居ることで上の規律を満たす）。
- **[罠] ヘッダ依存**: 各 `.rel` は全ヘッダに依存させる。怠ると構造体を変えたときに一部だけ再コンパイルされず、
  新旧のレイアウトが混ざってメモリを壊す（実際に踏んだ）。
- 冷たいコードは `--code-loc 0xA000` で単独リンクし、`--bank N` で rompack がバンクへ入れる。
- **バンクから常駐関数を呼ぶ2パス**: ①常駐を先にリンク（`rom.noi` に全 global の番地）→
  ②`tools/gen_symdefs.mjs` が絶対 EQU の `resident_syms.s` を作る → ③バンク側をそれと一緒にリンク。
  中ボスの背景弾の入口（`hb_*`）も、この仕組みで `hot_ram + 3*slot` の番地として注入している。

### リンク後の機械検証（Makefile が全部やる）
1. 常駐コード ≤ 24KB（rompack）
2. `_ramexec_page2_to_ram` < 0x6000、`_overlay_load` < 0x6000
3. 割込み文脈の6シンボル（`ras_apply`/`ras_rearm`/`ras_isr`/`sfx_update`/`bgm_update`/`snd_isr`/`sound_init`）< 0x6000
4. 常駐 `_DATA` の末尾 `s__HEAP` ≤ 0xE000
5. `hot.bin` ≤ `HOT_CAP`
6. 各 `ovl*.bin` のサイズ上限と、**オーバレイの static ≤ 256B**

### ビルドの切替
`DEBUG_FPS`（FPS表示）／`DEBUG_PROF`（µs 計測）／`NO_RAMX2`（page2 の RAM 実行だけ無効）／
`DEBUG_NOSEA`・`DEBUG_NOENT`（切り分け）／`MAGTEST`・`HSTEST`・`BGTEST`（実機検証用の専用ROM）。
切り替えたら `make clean` してから作ること。

### turboR 専用の前提
- 起動時 `sys_init()` が R800（ROM モード）へブースト。version<3 の機械では自動スキップ。
- SDCC の生成命令は Z80。`-mr800` は不採用。
- MSX2+ 互換は捨てている（割込み・速度の前提を専用化しているため）。

## 5. 実機/エミュ検証

- ビルド: `make` → `GAME.ROM`（**512KB** ASCII8 MegaROM）。版は `VERSION` が単一の真実。
- openMSX では C-BIOS を turboR のハードで動かす機種定義（`tools/openmsx/CBIOS_turboR.xml`）を使う。
  **実機ではまだ動かしていない**（ROM 転送のハードが未着）。テストプレイは WebMSX の turboR。
- 踏んだ罠（詳細は [苦労と教訓](苦労と教訓.md)）:
  - 塗りは **LMMV**（ピクセル単位）。HMMV はバイト単位で G4 では縞になる。
  - `vdp_cmd_wait` は **di 保護必須**（S#2 選択中に割込みが入るとハングする）。
  - スプライトの停止マーカは **Y=216**（212ライン表示では 208 では終端にならない）。
  - スプライトの X/Y は u8。画面外は**描かない**（折り返して反対側に幽霊が出る）。
  - ヘッドレスの openMSX は screenshot が更新されないことがある。見た目の確認は **VRAM から描き直す**。
